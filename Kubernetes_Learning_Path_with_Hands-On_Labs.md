# Kubernetes Learning Path with Hands-On Labs

Since you're already using **Minikube**, **kubectl**, **Ingress**, and **Deployments**, here's a practical Kubernetes learning path with hands-on exercises after every topic.

---

# Module 1: Kubernetes Fundamentals

## Learn

- Introduction to Kubernetes
- Architecture
- Control Plane
- Worker Nodes
- Containers vs Virtual Machines

## Lab 1: Create Your First Cluster

### Objectives

```powershell
minikube start
kubectl cluster-info
kubectl get nodes
kubectl get namespaces
```

### Verify

Expected output:

```text
NAME       STATUS   ROLES
minikube   Ready    control-plane
```

1. What is the Control Plane?
2. How many nodes exist in the cluster?

# Module 2: Pods

## Learn

- Pod concept
- Multi-container Pods
- Executing commands inside Pods

## Lab 2: Create an NGINX Pod

Create `pod.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
  - name: nginx
    image: nginx
```

Deploy:

```powershell
kubectl apply -f pod.yaml
kubectl get pods
```

Inspect:

```powershell
kubectl describe pod nginx-pod
kubectl logs nginx-pod
```

Exec into Pod:

```powershell
kubectl exec -it nginx-pod -- sh
```

### Challenge

Find the NGINX version:

```bash
nginx -v
```

# Module 4: Deployments

## Learn

- Rollouts
- Rollbacks
- Revision History

## Lab 4: Deployment Lifecycle

Create deployment:

```powershell
kubectl create deployment web --image=nginx:1.25
```

Scale:

```powershell
kubectl scale deployment web --replicas=5
```

Upgrade:

```powershell
kubectl set image deployment/web nginx=nginx:1.26
```

View history:

```powershell
kubectl rollout history deployment web
```

Rollback:

```powershell
kubectl rollout undo deployment web
```

### Challenge

Add a change cause:

```powershell
kubectl annotate deployment web kubernetes.io/change-cause="Upgrade nginx"
```

# Module 10: Ingress

## Learn

- HTTP Routing
- Host-Based Routing
- Path-Based Routing

## Lab 10: Route Traffic with Ingress

Enable Ingress:

```powershell
minikube addons enable ingress
```

Deploy application:

```powershell
kubectl create deployment web --image=nginx
kubectl expose deployment web --port=80
```

Create `ingress.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
spec:
  rules:
  - host: practice.local
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web
            port:
              number: 80
```

Apply:

```powershell
kubectl apply -f ingress.yaml
```

Test:

```powershell
curl http://practice.local
```

### Challenge

Create another service and route it through:

```text
/api
```

using the same Ingress object.

# Module 11: Production Readiness

## Learn

- Liveness Probes
- Readiness Probes
- Resource Requests
- Resource Limits

## Lab 11: Add Health Checks

Add probes:

```yaml
livenessProbe:
  httpGet:
    path: /
    port: 80

readinessProbe:
  httpGet:
    path: /
    port: 80
```

Add resources:

```yaml
resources:
  requests:
    cpu: "100m"
    memory: "128Mi"
  limits:
    cpu: "500m"
    memory: "512Mi"
```

Verify:

```powershell
kubectl describe pod
```

### Challenge

Intentionally misconfigure the readiness probe and observe deployment behavior.
